# TypeN Firmware Installer

Cross-platform USB firmware installer and recovery utility for TypeN hardware.

The application uses:

- Python 3.11+
- PySide6
- pyserial
- esptool

The source launcher automatically installs missing Python dependencies from
`requirements.txt` before starting the GUI.

## Device choices

The installer provides three hardware tabs:

- **P4 Pico** — TypeN with an external ESP32-C6 Wi-Fi module
- **P4 Pico WiFi** — TypeN with the onboard C6
- **C6 Wi-Fi Module** — firmware for the external ESP32-C6 module

Each tab validates the target chip before flashing a firmware package.

## Firmware packages

The recommended consumer package is a `.zip` file containing one complete
TypeN firmware package. The ZIP may contain the package directly or inside one
single top-level folder.

A valid package contains `flasher_args.json` plus every file referenced by its
`flash_files` table. Exact ESP-IDF filenames and relative paths are preserved.

Example package contents:

    flasher_args.json
    TypeN.bin
    ota_data_initial.bin
    bootloader/bootloader.bin
    partition_table/partition-table.bin

The installer extracts ZIP packages into a private temporary folder, validates
the package, flashes from that temporary copy, and removes the temporary files
when the package is replaced or the application exits.

Package folders are still supported for development builds through **Use
Folder**.

For safety the ZIP loader rejects path traversal, symbolic links, encrypted
archives, multiple embedded firmware packages, and unexpectedly large archives.

## Firmware filenames

TypeN Firmware Installer deliberately keeps the exact filenames and relative
paths generated by ESP-IDF in `flasher_args.json`.

For example, if ESP-IDF says:

    "0x10000": "TypeN.bin"

then the release package contains `TypeN.bin`.

Do not rename application, bootloader, partition-table, or OTA-data images
inside a release package.

## Creating a portable firmware package

From an ESP-IDF build directory:

### Windows

    py -3 tools\package_firmware.py C:\path\to\build C:\path\to\release

### macOS / Linux

    python3 tools/package_firmware.py /path/to/build /path/to/release

The packager reads `flasher_args.json`, copies that JSON file, then copies every
binary referenced by `flash_files` while preserving the exact relative paths.
The resulting folder can be zipped normally for consumer distribution.

## Normal installation workflow

1. Connect TypeN to the computer by USB.
2. Open the matching hardware tab.
3. Select the USB serial port.
4. Choose the firmware `.zip`, or drag it onto the installer.
5. Confirm the package reports **Ready**.
6. Select **Install Firmware**.
7. Keep the device connected until the installer reports success.

The installer uses the chip, flash settings, offsets, and filenames from
`flasher_args.json`; it does not hard-code generic ESP32 offsets.

## Check Connection

**Check Connection** asks esptool to identify the connected chip. It is useful
when more than one serial device is connected or before recovery work.

## Advanced / Recovery Tools

Advanced tools are hidden by default to keep the normal install workflow
simple. Expanding **Advanced / Recovery Tools** exposes:

- serial speed
- full-flash backup
- full device erase
- reserved direct-update control

### Erase Device

**Erase Device** performs an esptool whole-flash erase. This removes firmware,
settings, OTA state, and every other item stored in SPI flash. Firmware must be
installed again afterward.

### Full Flash Backup

**Save Full Flash Backup** reads from address `0` through `ALL`, allowing
esptool to use the detected flash size rather than a hard-coded device size.

### Direct Firmware Update

The direct update button remains intentionally disabled. A TypeN installation
can boot factory, `ota_0`, or `ota_1`, so a safe direct updater must first read
the device partition table and OTA selection state before choosing a target.

Normal full-package installation remains the supported recovery/install path.

## Windows

Double-click:

    run_windows.bat

The launcher searches for the Windows `py` launcher first, then `python`.
If PySide6, pyserial, or esptool are missing, `run.py` installs them into the
active Python environment and opens TypeN Firmware Installer.

You can also run:

    py -3 run.py

from PowerShell, Command Prompt, or the VS Code terminal.

## macOS

From the TypeN Flasher folder:

    python3 run.py

The first run installs the required Python modules automatically. Serial ports
usually appear as `/dev/cu.usbmodem...` or `/dev/cu.usbserial...`.

## Linux

Run:

    python3 run.py

or:

    chmod +x run_unix.sh
    ./run_unix.sh

Linux users must have permission to access the serial device, commonly through
membership in `dialout` or `uucp`.

## Python dependency bootstrap

`run.py` uses only the standard library until dependencies have been checked.
It verifies PySide6, pyserial, and esptool, then installs `requirements.txt` if
necessary.
