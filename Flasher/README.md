# TypeN Flasher

Cross-platform UART flashing utility for TypeN hardware.

The application uses:

- Python 3.11+
- PySide6
- pyserial
- esptool

The source launcher automatically installs missing Python dependencies from
`requirements.txt` before starting the GUI.

## Device sections

The GUI is split into:

- **P4 Pico**
- **P4 Pico WiFi**
- **C6 Slave**

Each profile validates the target chip before using a firmware package.

## Firmware package names

TypeN Flasher deliberately keeps the exact filenames and relative paths
generated by ESP-IDF in `flasher_args.json`.

For example, if ESP-IDF says:

    "0x10000": "TypeN.bin"

the release package contains `TypeN.bin`.

If ESP-IDF says:

    "0x10000": "network_adapter.bin"

the C6 release package contains `network_adapter.bin`.

Do not rename the application binary inside a release package.

The same rule applies to:

    bootloader/bootloader.bin
    partition_table/partition-table.bin
    ota_data_initial.bin

This avoids maintaining a second flash-layout convention.

## Creating a portable firmware package

From an ESP-IDF build directory:

### Windows

    py -3 tools\package_firmware.py C:\path\to\build C:\path\to\release

### macOS / Linux

    python3 tools/package_firmware.py /path/to/build /path/to/release

The packager reads `flasher_args.json`, copies that JSON file, then copies every
binary referenced by `flash_files` while preserving the exact relative paths.

A release therefore contains only the artifacts needed for a reproducible full
UART flash. No merged image is required.

## Windows

### Quick start

Double-click:

    run_windows.bat

The launcher searches for the Windows `py` launcher first, then `python`.

If PySide6, pyserial, or esptool are missing, `run.py` installs them into the
active Python environment and then opens TypeN Flasher.

Python 3.11 or newer is recommended.

You can also run:

    py -3 run.py

from PowerShell or Command Prompt.

## macOS

Install Python 3.11 or newer. Homebrew is one common option:

    brew install python

Then from the TypeN Flasher folder:

    python3 run.py

The first run installs the required Python modules automatically.

The serial port will normally look similar to:

    /dev/cu.usbmodem...
    /dev/cu.usbserial...

If macOS blocks access to a USB/UART driver, install the appropriate driver for
the USB bridge used by the hardware and reconnect it.

## Linux

Install Python 3.11 or newer using the distribution package manager.

Then:

    python3 run.py

or:

    chmod +x run_unix.sh
    ./run_unix.sh

The first run installs missing Python dependencies automatically.

Linux users must have permission to access the serial device. Depending on the
distribution, that commonly means membership in `dialout` or `uucp`.

Example:

    sudo usermod -aG dialout "$USER"

Log out and back in after changing group membership.

Typical serial ports include:

    /dev/ttyUSB0
    /dev/ttyACM0

## Full Flash / New Board

1. Select the correct product tab.
2. Select the serial port.
3. Choose **Select Package Folder**.
4. Point the application at a packaged firmware directory containing
   `flasher_args.json`.
5. Review the displayed offsets/files.
6. Select **Full Flash / New Board**.

The application uses the chip, flash settings, offsets and filenames from
`flasher_args.json`.

It does not hard-code generic ESP32 offsets.

## Identify

**Identify** connects to the selected device through esptool and reports its
flash/chip information in the log.

The profile supplies the expected chip:

    P4 Pico       -> esp32p4
    P4 Pico WiFi  -> esp32p4
    C6 Slave      -> esp32c6

A mismatched device will cause esptool to reject the connection/operation.

## Full Erase

**Full Erase** runs the esptool whole-flash erase operation.

This removes:

- application firmware
- bootloader/OTA state
- NVS/settings
- every other item stored in SPI flash

The GUI requires confirmation before running it.

## Flash Dump

**Dump Flash** uses esptool's full-flash read support:

    address = 0
    size    = ALL

so the attached flash size is detected rather than being hard-coded in the
application.

Choose an output `.bin` file when prompted.

## Firmware Update

The Firmware Update button is intentionally disabled in this first backend.

A TypeN P4 installation can boot factory, `ota_0`, or `ota_1`, and the C6
layout also contains OTA state. Writing only the `app.offset` from
`flasher_args.json` is not sufficient to guarantee that the newly written
image will be the image selected at the next boot.

The update implementation therefore needs to read the device partition table
and OTA selection state before choosing a destination.

This is preferable to shipping a convenient but unsafe "write 0x10000"
operation.

The final user workflow will still be:

    select current TypeN.bin / network_adapter.bin
        ->
    Firmware Update

The slot/state handling will remain internal to the flasher.

## Python dependency bootstrap

`run.py` itself uses only the Python standard library until dependencies have
been checked.

It tests for:

    PySide6
    pyserial
    esptool

If one or more are missing it runs:

    python -m pip install -r requirements.txt

and launches the GUI after installation succeeds.

When TypeN Flasher is eventually distributed as a packaged executable, these
libraries can be bundled and no runtime installation step will be necessary.
